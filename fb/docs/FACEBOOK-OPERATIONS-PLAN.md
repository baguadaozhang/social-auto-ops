## 1. 先明确：Facebook 不能照搬领英

| 维度 | 领英（现状） | Facebook（本计划） |
|---|---|---|
| 账号形态 | 个人号为主 | 个人号（管理员）+ 已有公司主页（对外资产） |
| 主要玩法 | 信息流评论、关注、发帖 | 主页内容、群组（人工）、Messenger、广告 |
| 自动化边界 | 浏览器拟真操作个人号 | **只有公共主页有官方 API**；个人号/群组无合规自动化通道 |
| 对卫浴出口的价值 | 直接触达采购/工程师，B2B 询盘快 | 客户背调时的品牌可信度、区域买家、后续再营销/广告 |
| 短期预期 | 已有测试数据 | 自然流量询盘会明显少于领英，前 60 天以“登录观察 + 建内容”为主 |

**结论**：Facebook 是“品牌门面 + 区域覆盖 + 以后投广告”的渠道，不是领英的替代品。
两条线内容可复用，但节奏和风险控制必须分开。

## 2. 现状盘点（2026-11-25）

- 个人号：**已有**，久未使用，但**从未被限制**——风险主要是“久未登录可能触发验证”，不是封号史。
- 公共主页：**已有公司主页**——不重复建，先查主页状态、管理员、能否正常发布。
- 项目环境：`profiles/facebook` 不存在、9223 未启动，账号尚未接入本项目专用环境。
- 代码：`config.yaml` 已有 facebook 配额与端口 9223；`src/platforms/facebook.py` **只实现了发帖**，评论/关注未实现。
- 注意：现有 `facebook.py` 的发帖入口是个人首页的「在想什么」，发的是**个人时间线**，不是公共主页；接入主页 API 之前，不要拿它跑这个现有账号。
- 结论：**资产不是从 0 开始，账号风险可控**。先登录观察与体检，再谈自动化；主页是资产，个人号只是钥匙。

## 3. 账号体系与“观察优先”要求

### 3.1 三个东西，各管什么

| 资产 | 作用 | 谁持有 | 能不能自动化 |
|---|---|---|---|
| 个人号（Profile） | 登录、当主页管理员、日常点赞/评论/加人 | 真人员工 | ❌ 不能；浏览器脚本代操作 = 高危 |
| 公共主页（Page） | 企业对外的品牌门面，客户点进来看到的东西 | 公司（可多人管理） | ✅ 官方 Graph API 可发帖/回评 |
| 业务资产组合（BM） | 把主页、广告账户、人员权限装在一起；生成长期 token | 公司 | —（管理后台） |

> 主页是店面，个人号是钥匙，BM 是公章柜。**钥匙可以换，店面不能丢**——所以主页至少留 2 个管理员。

### 3.2 登录后先看：只是休眠，还是被拦

按目前信息，最可能是“休眠后正常”；下表用于登录后核对：

| 看到的现象 | 判断 | 处理 |
|---|---|---|
| 能登录，无提示，发帖/评论/加好友都正常 | 休眠后正常 | 进入 3–7 天观察期 |
| 能登录，但发帖/评论/加好友有某项被限 | 功能限制 | 按页面提示申诉或等解除；解除前不跑自动化 |
| 登录要求身份验证/视频自拍 | 风控复核 | 人工完成，48 小时看结果；**不要重复提交** |
| 提示账号被停用/disabled | 停用 | 走官方申诉；同时准备第二个健康账号接管主页 |
| 主页本身无法发布/被限制 | Page 限制 | 单独查 Page 质量，和个人号分开处理 |

> 判断结论只有三种：**可用 / 部分受限 / 不可用**。三种对应三套节奏，不要混。

### 3.3 观察期做什么（3–7 天，人工）

- 固定设备与线路：就用这台机器、这个专用 Chrome、这条网络，不换节点、不换国家；
- 每天登录 10–15 分钟：刷首页、看 2–3 条视频、点赞 2–3 条，像正常人；
- 第 2–3 天发 **1 条无链接** 的生活/工厂图（不带网址、不带联系方式）；
- **不加陌生人、不进小组、不群发、不发外链、不跑任何脚本**；
- 每天记一行：能否发帖、有无提示、哪些功能可用——这就是观察期的证据；
- 稳定 3–7 天后再加第二个管理员、再谈 API。

### 3.4 保护主页的三件事（比账号本身更重要）

1. **主页至少 2 个管理员**：一个是你这个号，另一个用健康账号（同事/老板本人），避免单点丢失；
2. **BM 认领主页**：把主页装进公司业务资产组合，人员权限可交接；
3. **系统用户 token 发帖**：API 走 BM 系统用户，不依赖个人号每天登录；个人号只做人工维护。

> 如果个人号最终不可用，主页仍可通过另一个管理员接管；**不要为了保号去买号/接码，也不要在同一台设备上立刻注册新号**（容易被关联）。

### 3.5 启动顺序（先观察，后自动化）

1. **人工登录**：双击 `fb\start_fb.bat`，专用 Chrome（9223）打开 facebook.com，人工完成登录与可能的验证；
2. **查状态**：账号质量（Account Quality）、支持收件箱（Support Inbox）、主页质量（Page quality）；
3. **观察期**：按 §3.3 人工活跃 3–7 天，记录每天状态；
4. **补资产**：加第二个主页管理员 → 建/进 BM → 认领主页 → 生成系统用户 token；
5. **接 API**：先发 1 条测试帖，再排内容；
6. **内容运营**：每周 3 帖 + 人工群组互动 + 回复询盘。

> **运行环境**：Chrome 与 `main.py` 请在 **DSH 外**运行（双击 `.bat` 或普通 cmd）。
> 当前 DSH 会话对 `data/`、`profiles/`、`.venv` 这类运行目录没有写/执行权限，
> `main.py login` 会在初始化数据库时报 `unable to open database file`。
> 登录用 `fb\start_fb.bat`，验证用 `fb\check_fb.bat`；两者都是纯 ASCII、双击即可。
>
> **网络**：`fb\start_fb.bat` 已显式走 `http://127.0.0.1:7897`（Clash Verge 混合端口）。
> 若出现 `ERR_CONNECTION_TIMED_OUT`：先确认 Clash 在运行、节点可用；再**完全关闭旧的 FB Chrome**后重开
> （旧进程不会应用新的 `--proxy-server` 参数）。端口不同就改 bat 里的 `PROXY` 一行。

## 6. 技术路线

### 6.1 推荐主路径：公共主页 Graph API + 系统用户 token

- 接口：`POST https://graph.facebook.com/v27.0/{page_id}/feed`，参数 `message`、`link`、`published`、`scheduled_publish_time`
- 评论回复：`GET /{post_id}/comments` + `POST /{comment_id}/comments`（需 `pages_manage_engagement`）
- 权限：`pages_manage_posts`、`pages_read_engagement`、`pages_manage_engagement`
- 令牌：BM 里建**系统用户** → 分配主页 → 生成长期 token（不会 60 天过期），放环境变量，不写进仓库
- 关键好处：**发帖不依赖个人号登录**，个人号只负责管理员与人工互动；即使个人号再被要求验证，主页内容不受影响
- 审核：只管理**自有主页**、操作者本人是 App 管理员时，开发模式通常就能调通；一旦要服务别人/多主页，才需要 App Review 与业务验证（以 Meta 后台提示为准）
- 落地：新增 `src/platforms/facebook_api.py`，复用现有 `poster` 的配额/时间窗/日志；`content/posts.md` 的稿子可直接复用

### 6.2 不推荐：个人号浏览器自动化

- 现状 `facebook.py` 的发帖是 DOM 操作，选择器已脆；把它扩展到评论/关注，等于在 FB 风控最严的地方裸奔
- 个人号/群组的自动化**没有官方通道**（Groups API 已下线），浏览器脚本属于“非授权自动化”
- 这个账号久未使用，**任何脚本动作都可能触发复核**，得不偿失
- 结论：个人号只做人工；浏览器适配器保留作手动兜底，不纳入日常调度

### 6.3 能做 / 不能做

| 动作 | 官方 API | 建议 |
|---|---|---|
| 主页发帖、定时发帖 | ✅ | 主路径，观察期后每天 ≤2 条 |
| 读取/回复自己主页的评论 | ✅ | 可用，回复要像真人 |
| 读取主页洞察数据 | ✅ | 用于周报 |
| 去别人主页/群组评论 | ❌ | 人工，每天 ≤3 个群组 |
| 个人号加好友、群发私信 | ❌ | 禁止 |
| 抓取用户/群成员数据 | ❌ | 禁止 |

## 7. 风控红线

1. **久未使用的账号先观察 3–7 天，不跑自动化**；个人号始终只人工操作，自动化只走主页 API。
2. **主页至少 2 个管理员**；BM 认领；系统用户 token 兜底，避免单点丢失。
3. **一机一号一 IP**：不买号、不接码、不多号同 IP；不要在停用后立刻同设备注册新号。
4. 观察期：不加陌生人、不进组、不群发、不发外链、不跑脚本。
5. 观察期结束后：加人 ≤5/天；群组互动 ≤3 个/天；主页发帖 ≤2/天。
6. 不买粉、不买赞、不买群、不群发 Messenger。
7. 出现 checkpoint / captcha / “账号受限”：立即停 24 小时，人工处理，不重试、不换号硬上。
8. 素材与文案人工过一遍再发；AI 只做初稿，不做最终发布决策。
